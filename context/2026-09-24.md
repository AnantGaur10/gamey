## 3. Adapter concept (what it is)

- Adapter = thin wrapper module between game and portal SDKs. Game never calls `CrazyGames.SDK.*` / `PokiSDK.*` directly.
- Game calls only: `adapter.gameplayStart()/gameplayStop()/loadingStart()/loadingStop()`, `adapter.requestMidgame()/requestRewarded()/showBanner()/hideBanner()`, `adapter.loadProgress()/saveProgress()/getUser()`.
- `NoopAdapter` (basic): instant no-fill resolve, never blocks, never freezes. Rewarded buttons hidden or grant fallback, never dead-clickable.
- `CrazyGamesAdapter` (full): pause + block UI + mute on request, resume only on `adFinished/adError`, `adError` = no reward + continue.
- Switched by build flag, e.g. `BUILD=basic | full` (env define / separate entry). Bundler tree-shakes unused impl so basic contains zero SDK bytes. Lint rule: `src/game/` may not import SDK.

## 5. Engine decision

- Required: `HTML/CSS/(JS/TS)`, lean build.
- Chosen: **TS + Vite + raw Three.js + `cannon-es` (ragdoll only)**.
- Why not Unity/Godot: WebGL exports blow CrazyGames budgets (`initial ≤50MB, ≤20MB for mobile homepage, total ≤250MB, ≤1500 files`), Unity+iOS disabled by default, slower loads. Why not Phaser: 2D, wrong for 3D duel. Why not Babylon/PlayCanvas: heavier than needed for stationary duel.
- Vite does NOT increase payload: dev server/HMR not shipped, `vite build` (Rollup) tree-shakes + code-splits. Config: `assetsInlineLimit: 0`, manual chunks (three/cannon/game), lazy gun/character packs after `GameplayStart`, glTF+Draco/meshopt, 1024 textures, no source maps in builds, size CI (fail if initial >20MB).

## 6. Game concept (locked)

- Cowboy shooting duel. Player stationary (position fixed), hands/aim move after countdown, shoot opponent in front. Very little movement except ragdoll on death. Multiple guns + multiple character models.
- Perspective: **third-person** (see own cowboy too, not first-person hands-only).
- POV: **NOT over-shoulder**. Side-view 3/4 like Pokemon Showdown idea (correction: Showdown is side-on 2D, both in profile facing each other). Camera fixed perpendicular to duel line, ~15° front offset + slight elevation, narrow FOV ~30° (near-orthographic feel, keeps depth + ragdoll drama). Both full bodies in frame at `800x450` mobile through `1920x1080`.
- Round start pose: both player + opponent **aim pointed down** like real cowboy standoff. Raise on `DRAW!`. Aim movable until `DRAW!`, fire locked before (foul/misfire on early shot).
- Art: **custom low-poly, make (not buy)**. No IP/clone risk, smallest size. v1 = **procedural blocky cowboys in code** (approved as "this works"): primitives (boxes/capsules/cylinders) in joint hierarchy (shoulder/elbow/wrist pivots + gun socket), flat-shaded, 300-800 tris, ~10KB. Swap to Blender GLB later with same joint names, no logic change. Roster variant = colors/hat/gun dims + stat table.

## 7. Modes + HP + ammo (locked)

- Two modes:
  - **Best-of-N**: N rounds, both reset to **full HP each round**. Winner = most rounds.
  - **Deathmatch (endless)**: runs of **3 duels vs different characters, looped infinitely** (how long can you beat AI). Player has **1 life total** for whole run (no full refill). **+10% max HP per round won** (clamped to max, approved as "10% bump seems fine"). Score = streak. Lose once = run over.
- Ammo: **revolvers are 6-shooters, 6 shots per duel** (not 1 projectile per draw). Duel ends when someone dies **OR ammo runs out of either party** -> higher HP remaining wins (user phrasing: "least health" decides loser).
- Chamber cooldown after each shot, **longer than bullet flight time**, so realistically max ~1 airborne bullet at once ("anyone can't shoot 2 before dying").
- Damage: **depends on gun** (gun stat table: `drawMs, spread, damage/power, handling`). No fixed hits-to-kill; fast duels assumed (headshot ~1, body ~2 by tuning, not hard rule).
- AI scaling: Best-of-N **3% faster per round** (`*0.97`), **6% per level** (`*0.94`). Formula: `reaction = base * 0.97^roundIndex * 0.94^levelIndex`, floor **180ms** (never unreadable). User explicitly does NOT want large per-round drops.
- Blood: **none**. Dust puff only (PEGI-12, 13+ safe).

## 8. Projectiles (not hitscan, locked)

- Pooled meshes + fixed-step ballistics (`pos += vel*dt`, slight gravity, life timeout). Spawn at muzzle world pos along barrel dir.
- Collision = sphere vs opponent capsule/hitboxes per fixed step. Deterministic, replayable, net-ready (`Fire{pos,dir,gunId,tick}`).
- Cost trivial for 1-2 bullets; fine on 4GB Chromebook + mobile. Life = `distance/speed + 1s` margin.

## 9. Ragdoll (true physics, locked)

- Not baked fall. Each cowboy gets low-bone ragdoll (~8 bodies: pelvis/torso/head/upper-arms/legs) in `cannon-es`, kinematic while dueling. On bullet impact: switch to dynamic + `applyImpulse(bulletDir * gunPower, hitPointWorld)` + torque. Pose emerges from hit point.
- Frame-independent via **fixed 60Hz accumulator** (`acc += min(frameDt,100ms); while(acc>=step){world.step(step)}`), render interpolates. Same outcome at 60/144/165Hz (CrazyGames requirement). Sleep + cull after settle for mobile perf. Do NOT use Rapier/WASM (heavy).

## 10. Ticks vs refresh rate (asked + answered)

- `fireTick` / time counting does NOT depend on refresh rate. Logic ticks fixed 60Hz, render runs at monitor Hz and only interpolates. High-Hz looks smoother, no gameplay advantage.

## 11. Round events: time-of-day (locked)

- Time passes each round in single game: **R1 noon (neutral white, high vis) -> R2 evening (orange low sun, long shadows) -> R3 night (dark blue, very low opponent visibility) -> R4+ cycle/stay night**.
- Impl: lerpable `fog + hemi/dir light color/intensity + skybox gradient + lantern props` in `render/`, driven by `roundIndex`. No extra textures (budget-safe).
- Night = silhouette + rim only (~15% ambient on enemy) + muzzle flash + `DRAW!` cue + minimal outline. Must stay readable at DPR=1 or QA fails. Not pitch black.

## 12. Double KO -> hell sudden-death (locked)

- If both die -> **increment total rounds by 1 extra round**, mid-game map swap (no reload) to **hell/nether realm**: dark rock ground, emissive lava strips (scrolling shader, no particles for perf), red fog/lighting, black-red sky. Lazy-loaded after `GameplayStart`.
- Rule (final): **Double KO = shooter's bullet was already airborne AND lethal-if-it-hits, fired before own death resolved.**
  - `lethal = gunDamage >= target.hpAtFireTime` (HP only drops mid-duel, heals only between rounds, so fire-time check stable).
  - Must actually hit + kill; lethal-but-missed does not count.
  - Non-lethal final blow can never force double KO (locked).
  - With 6-shooters: **any lethal in-flight bullet counts** (not only last fired); cooldown makes 2-in-flight unlikely.
  - Earlier considered fixed 250ms window: rejected (breaks with varying distance/projectiles). Earlier `flightTime + 120ms` idea superseded by fired-before-death rule (distance/speed/refresh-rate drop out).
- Hell round rules: **both get 1 bullet only**. If **both miss -> another hell round** (loop until someone hits). Winner takes point / continues run.

## 13. Per-round variance (locked)

- Every round different: **distance `uniform(9,14m)`** + small lateral offset + camera auto-dolly (`camDist = base + k*duelDist`). Player never leaves room; gap change noticeable so last round's head aim never reuses. Screen->duel-plane raycast uses current camera (auto-corrects sensitivity). Clamped to QA readability. Safe: projectiles/ragdoll same code path at any range.
