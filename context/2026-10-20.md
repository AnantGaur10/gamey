# 2026-10-20

## 1. Combat spec flake: wall-clock waits vs the fixed clock

The 2026-10-19 open item ("a shot kicks the crosshair x1.5" failing 3/3 at
desktop-1920) was neither the ladder nor the low-end changes:

- Passes alone (5/5), failed in-suite. A/B against a HEAD worktree (same
  machine, same moment): both trees draw ~175ms frames headless at 1920
  (software GL), 300-500ms under load, with the same tick counts after DRAW
  and no extra stall at DRAW (the working tree compiles one program there,
  the dust sprite).
- `frame()` clamps dt to 0.1s, so at 3-6fps the fixed clock runs at about
  half wall speed. The spec waited 500ms of wall time and then fired; that
  is 30 ticks at 60fps but only 12 in-suite (also 12 at a 6x CPU throttle),
  barely past `DRAW_TICKS` = 10, and under it on a slower frame: the shot
  was ignored (bloom ratio 1.0). The quick-draw test's 600ms wall wait hit
  the same wall (gun still "drawing").
- Fix (tests only): both tests wait on `__gamey.gun('player').tick -
  drawTick` (30 ticks before the shot, 54 for the 0.6s return, 36 for the
  quick-draw). The kick itself is exactly x1.5 at 0.5 / 1.7 / 3s after DRAW,
  throttled or not. Game timing untouched.

## 2. Two more spec flakes, same family + one ladder side effect

- `hell is one round` (1920): the first of six wall-clock-spaced clicks
  landed inside `DRAW_TICKS`, one round stayed in the cylinder, so the
  ammo-out end never came (foe 6/6 missed at 24m). Now: wait for the gun on
  the fixed clock, then click until the cylinder is empty or the round ends.
- `prone duelists keep fighting both ways` (mobile-800): ladder level 1
  (GREENHORN GUS, wobble 1.55, by design) at 25m emptied its cylinder at the
  prone player without a hit. The test now pins its duel through DEV
  `__gamey.round(0, 8)` (8m, old round-1 AI tier). Its last
  `waitForFunction(fn, { timeout })` passed the options as the page-function
  argument (20s ignored, ran into the 150s test timeout): fixed.

## 3. Low-end memory plateau (closes the 2026-10-15 task)

Headless 1366x768, `--enable-precise-memory-info`, forced GC before each
sample (scratchpad probe, `__gamey.info()` + a getContext counter):

- 32 round transitions (all four maps x noon / evening / night + hell, twice)
  then 14 menu <-> duel trips (tutorial -> SKIP -> home backdrop -> duel):
  ONE WebGL context and one canvas throughout, GL programs 46-54 (flat),
  textures 2-3, geometries ~116-123 once every set is cached (session GLB
  geometry stays on the GPU by design), JS heap 20.7 -> 21.5MB over the 14
  trips (levelling off), zero page errors.
- Measurement trap: a first run showed +0.43MB heap per trip, linear. Heap
  snapshot retainers: the duels were pinned by `<button>` elements held as
  "DevTools console" global handles, i.e. the ElementHandles that
  Playwright's `waitForSelector` / `page.click` returned and the probe never
  disposed (the SKIP button's click listener closes over its duel). With
  in-page clicks + boolean `waitForFunction`, flat. Memory probes must not
  hold element handles.
- Not done, numbers don't call for it: GLB quantization / meshopt, a
  lighter-FX tier (the frame watchdog stays the only shedder).
