# Context — 2026-10-02 (wound lottery: reactive movement)

## 1. Locked design (user decisions)

- Duelists stay rooted (no locomotion, no player/opponent movement control) but
  REACT to being shot: persistent wound poses via seeded lottery.
- Hit 1 → bend (50%) or lunge-crouch/kneel (50%). Hit 2+ → bend (40%) /
  crouch (35%) / full lying prone (25%). Prone unlocks only at 2+ hits but is
  never guaranteed (randomness). Weights are tunable constants, not balance.
- Prone duelists KEEP FIGHTING (fire back from the ground). No stat changes.
- Death rules untouched: headshot still instant-kills, 3 body shots still kill,
  a prone duelist dies to the next lethal hit. Wounds never gate lethality.
  ("Can only happen after 2" was ruled to mean prone unlock, NOT death gating
  — the latter would break headshot-instant + 3-shot TTK + double-KO lethality.)
- Rolls use the DuelMachine seeded RNG (`rollWound`) → deterministic per seed,
  free replay/net determinism, no extra Transport fields needed.
- Blender split: gross poses stay procedural (group-level, identical with or
  without GLB = fallback-safe); Blender authors one "wounded" breathing loop
  per cowboy (micro-motion only, composes instead of fighting).

## 2. Implementation (code)

- `DuelMachine`: `WoundPose` type + `rollWound(hitsTaken)` (lottery above).
- `projectiles.ts`: `CapsuleProfile` + `CAPSULE_FOR_POSE` (none/bend/crouch/
  prone: head 1.9/1.68/1.32/0.55, body segments lowered); `testCapsuleHit`
  takes a profile (default standing = zero behavior change unwounded). Prone is
  a vertical-capsule approximation of a horizontal body — stopgap until
  per-bone attribution lands.
- `home.ts`: `player/foeWounds` + `player/foeWound` per duel (fresh closure =
  auto-reset each round + on revive); triggers in `woundFoe` + `hitPlayer`
  non-lethal branches; `WOUND_POSE_TARGET` {pitch, roll, drop}; `woundStep`
  damped chase (6/s) in frame loop, skipped for corpses/dead; `refreshAimPlane`
  on foe wound; `foeScreen`/AI aim (`mid+0.12` preserves old 1.35 feel)/
  click-fallback/hit-defaults all consume live profiles; `playDeathFall`
  skips clips when prone (they're keyed from standing — snap risk), straight
  to ragdoll; `queueWoundClip` plays `"wounded"` loop 350ms after the flinch
  (no-op until GLB ships it); late GLB swaps resume the loop if wounded.
- Rotation order fix (real bug, found via screenshots): default XYZ Euler
  pitches about WORLD X — correct for the foe (yaw −61°) but leaned the
  PLAYER (yaw ~119°) BACKWARD. Both rigs now `rotation.order = "YXZ"`
  (`cowboy.ts`, `cowboyGlb.ts`): yaw first, pitch about local X (local +Z
  faces the foe both sides). Single-axis users (setFall/faceToward/rock) unaffected.
- Readability fix (chase-cam foreshortening): pure forward motion collapses
  along the view axis (prone = unreadable blob). Poses carry a sideways roll
  (bend .12 / crouch .15 / prone .5, toward gun side) — crumple reads clearly
  AND stays toward-foe. Firing-rock lines compose on the roll var (they share
  rotation.z). Verified: foe prone sprawls readable, player prone stays fully
  in frame with gun still tracking the foe.
- DEV-only `window.__gamey` probe (zero prod surface): `wounds()`,
  `capsule(side)`, `roll(n)`, `force(side, pose)` (pose forcing for visuals),
  `aimAt(side)` (screen px of live capsule mid, viewport-proof aiming).

## 8. Ragdoll sky-launch fix (build mode, model-health test run)

- Verdict first: **models are healthy, physics was broken.** GLB static audit:
  hero/outlaw 807/813KB, 79/80 nodes, 47 anims each, zero `St_` strays, all
  9 seam nodes (`armR/elbowR/gunTip/Pelvis/Torso/Head/Sleeve_L/Leg_L/Leg_R`)
  + `Knee_L/R` + `Waist` present. Live `__gamey.parts` dump: both duelists
  grounded at correct heights. No Blender work needed.
- Real bug (found via `__gamey.parts` T0/T+400ms dumps in
  `tests/zz-ragdoll-check.spec.ts`): corpses launched to **y≈7–11 and kept
  rising ~6m/s**. Root causes in `src/render/ragdoll.ts`: (1) full-size AABB
  boxes of adjacent parts interpenetrated at spawn (thigh pivots sit at ankle
  height, boxes started 0.3m under the ground plane) → depenetration pop;
  (2) parts collided with EACH OTHER, so the jointed clump jitter-climbed
  instead of falling (bodies==visuals proved sync innocent).
- Fix (`ragdoll.ts` only): boxes shrunk to 75% (min half 0.05), bodies
  clamped above ground at creation + in `follow()`, sibling self-collision
  OFF via collision layers (parts mask ground-only, ground collides all),
  damping 0.25/0.45→0.4/0.6. Result: settled corpse y 0.4–1.0, spread ~1m.
  Added `Ragdoll.bodies()` + `__gamey.bodies()` DEV probe (zero prod surface).
- Tests also de-flaked (test-only, no game logic): wounds prone test
  (200ms settle, 6 attempts, 500ms cadence, round-end break — was dying to
  live AI mid-loop), ragdoll spec rebuilt on the **tutorial dummy** (passive:
  deterministic kill; live-AI kill race is ~50/50 since both deal ~45/shot)
  with real asserts (≥5 parts, finite, −0.5<y<1.7, spread<6) + fast dump
  (routeAfter rebuilds the duel ~1500ms post-kill).
- Verified: `npm test` PASS (2.43MB) · 12/12 desktop-1920 (wounds+combat+
  ragdoll+visual) · 12/12 mobile-800 · typecheck clean.
- Still open: snappy wound-punch on non-lethal hits (planned, not built);
