## 8. Refresh-rate-independent physics + interpolated rendering (IN FLIGHT — see tasks/2026-10-04-next.md)
- Trigger: user said bodies "move janky and not smooth" (chose: dying bodies/ragdoll), then asked for it "fixed good", physics independent of device refresh rate, as spec-compliant as possible. - Diagnosis (code-read + measured): the ragdoll had its OWN accumulator (<=4 `world.step(1/60)`/frame) and `sync()` drew the LATEST step with no interpolation; bullet meshes were only repositioned inside the 60Hz step. Deaths are ragdoll-first (clips stopped before `doll.hit`), so authored fall clips were not the cause. Everything else was already dt-based (exponential damped chases, mixer, smoke, aim glide, wall-clock timers).
- BEFORE numbers (new test vs old ragdoll): duplicate-pose frames 50% @120Hz, 59% @144, 64% @165, 75% @240; 144Hz result deviated 5cm from 60Hz.
- Design implemented: one fixed 1/60s clock for ALL physics, render interpolates by `alpha = acc/STEP`.
  - NEW `src/game/fixedStep.ts`: `STEP`, `MAX_FRAME_DT` (0.1), `createFixedStepper().advance(dt, fixedFn) -> alpha` (dt clamp = spiral guard; 1e-9 epsilon so 0.1s = 6 steps). Pure, no THREE/DOM; shared by the game loop and the test.

Own snapshots, not cannon's `interpolatedPosition` (independent of cannon internals). `bodies()` stays raw physics truth.
  - `src/ui/home.ts` `frame()`: hand-rolled `acc` loop replaced by the stepper; `machine.step`, recoil recover, `stepBullets()` and ragdoll `fixedStep` all run inside the fixed callback; after it `doll.follow()` (live) / `doll.sync(alpha)` (corpse) and `renderBullets(alpha)`. Bullet views now carry `prev/cur` (`bulletsBeginStep`/`bulletsEndStep`/`renderBullets`); `STEP` is imported from fixedStep.ts (local const removed).
- NEW `tests/physics-refresh.test.ts` (`npm run test:physics`, now chained into `npm test`; pure Node, synthetic 10-part rig, no WebGL): 2.0s of sim at 30/60/120/144/165/240Hz + seeded jittered 60Hz.
