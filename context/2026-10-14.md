## 1. First-launch tutorial gate

User: "the game should directly hop into tutorial if its a first time player
use the sdk or storage class to check if its first time player account for
all possibilities and maintain compliancy to specs of crazygames.com"

- The CrazyGames SDK has no first-play signal (User module: username,
  avatar, id only). "First time" = nothing on this device or in the save says
  the player has played. `src/portal/firstLaunch.ts`, called from `boot()`.
- Signals, OR-ed: `Progress.tutorialDone` (SDK Data module, cloud-synced for
  logged-in users; SafeStore in no-SDK mode), the SafeStore device flag
  `gamey.tutorialSeen` (written synchronously on finish/SKIP), and veteran
  progress (gold, best streak/best-of, revive token, extra/equipped gun, a
  home-only setting: map choice or mute).
- Why the device flag: Data saves are debounced 1-30s (tab closed right after
  SKIP); a visit with the SDK blocked can't read the Data guest save; a login
  reloads the game (SDK does this with the Data module) onto an account save
  that may predate the tutorial; a Data call that throws at boot drops to
  SafeStore.
- A player found not new gets both marks written once, so the answer is
  stable. Corrupt / wrong-version save = defaults = tutorial (SKIP is one tap).
  Storage fully blocked = in-memory only, tutorial each new session.
- Spec fit (`specs/crazygames/quality-guidelines.md`, `account-integration.md`):
  land in gameplay, in-gameplay skippable tutorial, guests play, no login
  prompt, Data module first (local flag is a backup, not the only source).
  Shared-device trade-off: a second person on the same browser profile lands
  on home (HOW TO PLAY is on the menu).
- Checked headless (`?nosdk=1` and SDK local mode): fresh -> tutorial, SKIP +
  reload -> home, flag only -> home, veteran save -> home, tutorialDone save ->
  home, corrupt save -> tutorial, localStorage throwing -> tutorial, SKIP works.

## 2. Night surroundings on Telegraph Row and The Falls

User: "this map at night is very bad i cant see anything i need to see
something like the nearby houses at some level of visibility" (Telegraph Row,
round 3) and "also fix this map night time too ... i want them to be able to
see vaguely of the surroundings and upfront not the player but the trees and
things" (The Falls).

- Night difficulty stays fog (locked): fogDensity, fog colour (no lift), the
  duelists' light and the arena floor are untouched.
- `setGlb.ts` `addNightVis` (set paint / foliage / water only), stage 2 only,
  never hell: OFF the duel lane the set gets a flat moonlight fill
  (`diffuse x fill` emissive) and a lighter fog (fog distance x `fog`). The
  lane = |lateral| < 2.5m from the player->foe line, ramping to full effect at
  8m. Inside it the night is as before, so whatever sits behind the foe stays
  black (no silhouette), and the lane is depth-agnostic (no distance tell).
- Per map `MapDef.nightVis`: town `{ fill 0.12, fog 0.55 }`, falls
  `{ fill 0.14, fog 0.45 }` (more open, trees further). Saloon and Main Street
  have none.
- Look-dev captures: headless software GL drops the post pass (watchdog), so
  night looks brighter there than on a GPU. Slowing `performance.now` + the
  rAF timestamp (x0.05) in an init script keeps the post pass for captures.

  `killFoe`), when the round was already over, so it never showed. Now
  `lifesteal()` runs on every landed body hit: 20% of the damage actually

  Checked headless: 50 -> 57.6 HP on a 38-dmg hit at 7m.
- Gun finishes: `paintGun()` (`render/cowboy.ts`, `GUN_FINISH`) repaints the
  player's revolver metal: lifesteal red, gold gold, default untouched. GLB:
  the grey (low-saturation) COLOR_0 vertices are the metal, the wooden grip
  keeps its colour; geometry cloned (never the shared GLB data). Procedural
  fallback: grey part materials cloned + recoloured. Applied to the
  procedural player and again after the GLB swap. Foe guns stay default.
- Shop + revive overlay: inline SVG icons (revolvers in their finish, revive
  token = white first aid kit with a red cross).
- Tutorial rule card "DAMAGE & DISTANCE" -> "HEADSHOTS": "A headshot always
  kills." (falloff / range / ammo-out text dropped from the tutorial).
- Player-facing text never says "hell": round line `SUDDEN DEATH — FIRST HIT
  WINS`, double-KO sub "Sudden death: first hit wins.", the draw subs, the
  rule card. Code / asset names (hellRound, hell.glb, `__gamey.hell`) stay.
