## 1. Low-end devices + load times (work of 2026-10-15, landed today)

User (2026-10-15): "okay work on optimizing for 4gb ram chrome books and old
android and ios phones and load times". Spec: `specs/crazygames/technical.md`
§1-3 (4GB Chromebook / Safari performance gates, SDK `systemInfo` instead of
UA sniffing, DPR 1 on iOS + low-memory Android). Gameplay timings untouched.

- Boot: `basic.html` paints a pure HTML/CSS splash (title + bar) at once;
  `main.ts` dynamic-imports `ui/home` so the game chunks download WHILE the
  SDK script loads (a vite plugin keeps `modulepreload` links for that chunk
  + three/cannon). A failed chunk shows RETRY (reload). Rye font preloaded.
- One WebGL context for the session (`render/arena.ts` `acquireRenderer`):
  menu backdrop and duels share it; `arena.release()` frees what the arena's
  scene uploaded (`render/gpu.ts` `releaseScene`) and keeps compiled programs
  (`pinPrograms`), session GLB geometry (`keepOnGpu`) and module canvas
  textures (`keepTexture`). ShaderMaterials retire through `retireMaterial`
  (one live instance per source keeps three's program key stable; otherwise
  one leaked program per round). Never `forceContextLoss` an arena again.
- `arena.prepare(obj)`: `compileAsync` (KHR_parallel_shader_compile) before a
  late arrival (cowboy GLB, street, map set) joins the scene, and before the
  duel's first draw (canvas hidden over the CSS sky until then); the menu
  waits for it before each reveal. No extension: `compile()` and go.
- Session caches: parsed street + cowboy GLBs cloned per duel (sets were
  already); the procedural street is built only while the street GLB is
  still downloading or failed (`buildProceduralStreet`). Procedural hand-pose
  solve once per session. Audio HEAD probes memoized. Prod renderer:
  `checkShaderErrors` off (sync stall), DEV keeps it.
- Device tier (`render/device.ts`, `adapter.deviceInfo()` = SDK
  `user.systemInfo`, null without SDK): `lowMemory` (<= 4GB, iOS, or a touch
  device hiding its memory) -> pixel ratio ceiling 1x (1.5x other touch, 2x
  desktop; the frame watchdog only lowers it); `lowMemory`/`saveData` -> the
  menu backdrop stays on one map and a RANDOM series takes the backdrop's map
  (no second 1.2-1.7MB set download). Post pass stays on (watchdog drops it).
- Measured 2026-10-15 (headless, 4x CPU throttle, noisy machine, A/B vs a
  baseline worktree): round-start freeze 230-650ms (was 560-1,140ms), sync
  duel setup 60-125ms (was 550-800ms), the street in place on the first frame
  (was 0.5-1s later), GL programs plateau (no growth over 26 rounds), first
  paint = splash at ~0.3s instead of a blank frame until ~1s (4G) / ~4.4s (3G).
  The final prepare()-gated first draw was checked for errors and context
  reuse, not re-timed separately.
- Not done (numbers did not call for them): GLB quantization/meshopt, a
  lighter-FX tier.

## 2. Standard mode = a 10-level ladder

User: "for the standard mode create a level based system so after each duel
of 3 rounds it switches to the next npc have 10 levels in total with
different enemy npc each progressively difficult in response time and
accuracy they must look different also if u want can add female enemy npcs"

- `src/game/levels.ts` (pure): `LEVELS` = name, tagline, foe outfit,
  `reactionBaseMs`, `accuracyMult`, `focusQuality`; `levelAi(level, stage)`;
  `playableLevel(saved)`; `levelClearGold(level)` = 20 + 5 x level (first
  clear only; economy not locked).
- Ladder: 1 GREENHORN GUS (greenhorn) 950ms / 1.55 / 0.25, 2 BLACK BART
  (outlaw), 3 OLD MOSE (prospector), 4 EL VERDE (bandido), 5 CALAMITY KATE
  (kate, F), 6 THE PALE RIDER (ghost), 7 RUBY ROSE (ruby, F), 8 GENTLEMAN
  JACK (dandy), 9 MARSHAL COLE (marshal), 10 THE WIDOW (widow, F) 395ms /
  0.58 / 0.90. Reaction keeps the shared formula (x0.85 haste, x0.97^stage,
  floor 180ms): level 1 opens ~810ms, level 10's last round ~300ms. Inside a
  level's best-of-3 accuracy x0.95^stage and focus +0.04/stage (milder than
  the old tiers). Old AI_ROSTER tiers stay for deathmatch + DEV series.
- Flow: PLAY = `Progress.level` (next unbeaten, 0-based; 10 = cleared, then
  PLAY replays THE WIDOW). Win the best-of-3 -> saved at the deciding round
  (`endRound`, not the card), card says "<foe> is down. <next> is waiting.",
  "LEVEL n UNLOCKED" badge, primary NEXT: LEVEL n. Loss -> REMATCH, same
  level. Level 10 won -> LEGEND! + LADDER COMPLETE, PLAY AGAIN.
- UI: home PLAY subtitle "Level n of 10 · vs <Name>" (kept visible at
  <= 480px tall); the home backdrop's next standoff shows that foe
  (`showMenuScene(..., { foe })`, its GLB is then cached for the duel); round
  line "LEVEL n · NAME · ROUND r · YOU p – f · map · d M"; a level banner
  (level, name, tagline) fades in/out on a level's first round; result card
  kicker "LEVEL n OF 10 · map", the foe's name over its score.
- Deathmatch and the tutorial are unchanged (4-look cycle, outlaw dummy).
- DEV: `__gamey.level(n)` (1-based) starts a level, `__gamey.ai()` = the foe
  AI in effect.
