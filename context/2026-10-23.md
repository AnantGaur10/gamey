# 2026-10-23

## 1. First-load fixes (user: opened the game in a fresh Edge, the tutorial "didn't load")

- Root cause: `arena.prepare()` used three's `renderer.compileAsync`. Its
  poll does `properties.get(mat).currentProgram.isReady()` inside a
  `setTimeout`; a material disposed mid-compile has no `currentProgram`, so
  the poll threw `Cannot read properties of undefined (reading 'isReady')`
  and the promise never settled. The duel's first draw waits on
  `prepare(scene)`, so the canvas stayed `visibility:hidden` for good (HUD
  over the CSS sky, the duel running underneath). It needs
  KHR_parallel_shader_compile (ANGLE/D3D11: Edge, Chrome on Windows) AND a
  compile slow enough that a GLB lands meanwhile: on a cold first visit the
  procedural stand-in cowboys are compiled, then swapped (`swapCowboy`
  disposes their materials) while their programs still link. A warm Chrome
  (HTTP + GPU program cache) never hit it.
- Fix: `programsReady()` in `arena.ts` = our own poll over
  `renderer.compile()`'s material set: a material without a program
  (disposed) or with a ready one drops out, any throw drops it,
  `PREPARE_MAX_MS` (6s) caps a slow driver (the first draw then finishes the
  links). The menu backdrop uses the same `prepare()`.
- Repro (headless has no parallel-compile extension): an init script fakes
  `KHR_parallel_shader_compile` and reports `COMPLETION_STATUS_KHR` false
  for 1.5s after each `linkProgram`, fresh context, CDP throttle 2-4 Mbps.
  Before: canvas hidden forever + the pageerror. After: drawn ~3s in.
- Loading bar (user: "if u want to add a loading bar if the map hasnt
  completely loaded its fine"): `runDuel` holds a cold duel behind the boot
  splash's look (`.boot.duel-loading`: title, a real progress bar,
  `LOADING <MAP NAME>`) until both rigs + the set have swapped in and the
  first frame is drawn, `LOAD_MAX_MS` (20s) at most, then it plays on the
  procedural stand-ins as before. Bytes come from GLTFLoader's onProgress
  (`src/render/loadProgress.ts`, fed by cowboyGlb / streetGlb / setGlb);
  90% = downloads, the last 10% = drawn. Cached duels (`allLoaded`) never
  show it. Focus cannot start while loading (`beginFocus` gate, also during
  the hidden-canvas compile of a cached duel); a mouse already in the
  holster zone starts Focus when it lifts.
- Map draw calls / tris measured (DEV `__gamey.info()`, whole frame incl.
  cowboys + post, d 6/25): street 46-48 calls / 41k tris, saloon 35-38 /
  41k, falls 35-38 / 41k, town 36-41 / 48k, 44 programs. Already inside
  budget for low-end mobile; no set rebuild (each needs a Blender run +
  byte/vertex verification, for no visible gain). The cold-visit cost is
  shader programs (44), not geometry.

## 2. Ladder AI 10% harder (user: "increase accuracy by 10% of each enemy ai on each level and decrease response latency of them by 10% too")

- `src/game/levels.ts` LEVELS, every level: `reactionBaseMs` x0.9 and
  accuracy +10% read as hand wobble `accuracyMult` / 1.1 (lower wobble =
  more accurate; accuracy ~ 1/wobble), values rounded in the table.
  Old -> new: 950/1.55 -> 855/1.41 ... 395/0.58 -> 356/0.53.
- First shot after the x0.85 haste: level 1 ~810 -> ~730ms, level 10's last
  round ~300 -> ~285ms (the 180ms floor is unchanged). `focusQuality`, the
  per-round climb (0.97^stage, wobble 0.95^stage) and the deathmatch
  `AI_ROSTER` are unchanged.

## 3. Ladder reaction scaled so level 10 = 180ms (user: "keep the same ratios but have the level 10 ai have 180ms response time")

- Every `reactionBaseMs` x one factor k = 180 / (0.85 x 356) = 0.5948
  (rounded), so the level-to-level ratios of §2 hold and level 10's first
  shot (x0.85 haste) is 180ms, the floor; its later rounds clamp there.
- First shot per level, round 1 (ms): 433, 396, 360, 327, 298, 271, 246,
  223, 201, 180 (bases 509 ... 212). Accuracy (§2 wobble) unchanged.
- Consequence: level 1 is far quicker than before (~730 -> ~433ms).

## 4. Player name, SETTINGS, CrazyGames auth listener (user: "ask a username after tutorial is done how to add auth listener")

- CrazyGames compliance check first (Full Launch checklist): the username
  was fetched but never shown, and no Auth Listener existed. Store preview
  videos are still not made.
- Name rules (user: "if logged in take their name if not logged in ask a
  name that is skippable"; old players: "give them a random name"):
  - A CrazyGames account name always wins and is never asked for (account
    spec). `src/ui/names.ts` `displayName` = account name, else
    `Progress.playerName`, else "Stranger".
  - Guests: after the tutorial (SKIP or the rule cards' PLAY ->
    `afterTutorial`) the `.nameprompt` screen, prefilled with
    `randomCowboyName()`, die = another, OK / Enter keeps the typed name,
    SKIP (`[data-n=skip]`) keeps the random one. Shown once (a replay from
    HOW TO PLAY already has a name).
  - Saves from before names get a random name silently at boot.
  - `cleanName`: `[A-Za-z0-9 _.'-]`, spaces collapsed, max 16; empty is
    rejected. Every name goes through `escapeHtml` (`el()` is innerHTML).
    Single player: only the player sees it, so no moderation.
  - Shown on the home topbar chip (`.chip.pname`, opens SETTINGS) and on
    the result card's YOU side (`[data-pname]`).
- SETTINGS (user: "dim down sfx, music, change names, go to a lower
  graphics mode"): home option `data-m="settings"`, `showSettings` in
  home.ts. NAME (guest: input + die + SAVE, plus "Log in with CrazyGames"
  when the SDK has accounts: `adapter.requestLogin()` = `showAuthPrompt`,
  optional, never the main CTA; account: read-only name), SOUND FX and
  MUSIC sliders (`settings.sfx` / `settings.music`, 0..1, default 1; music
  = 0.5 x slider, saved but silent until music files exist), GRAPHICS
  HIGH / LOW (`settings.quality`, the old unused field).
- LOW graphics = `setLowGraphics` in arena.ts: pixel ratio 1 and no post
  pass, the path the slow-frame watchdog already falls back to. The menu
  backdrop is rebuilt on toggle. Checked: first-frame canvas ratio 2 (HIGH)
  vs 1 (LOW) at DPR 2; headless software GL drops to 1x within ~2s anyway.
- SFX volume: `AudioManager.setSfxVolume` scales the synth bus (gunshots,
  wind) and hit sounds; mute still wins.
- Auth Listener: `CrazyGamesAdapter` registers `user.addAuthListener` when
  accounts exist and forwards the name through `adapter.onUserChange`.
  boot() re-renders home (or updates `[data-pname]` and the SETTINGS name
  row). A logout without a guest name gets a random one. Saves need nothing
  (the SDK reloads onto the account's Data save, see firstLaunch.ts).
- Tests: every helper that clicks `.skip button` now also clicks
  `.nameprompt [data-n=skip]`. Checked headless at 1920 / 907 / 800 with a
  fresh profile (name screen, cleaning, reload, rename, sliders, LOW,
  veteran save, no page errors) and in SDK `local` mode (User1 shown, no
  prompt, a fired login / logout renames live).
