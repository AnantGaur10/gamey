## 1. AI-driven Playwright test (2026-09-28)

- **Motive**: Create a testing solution where AI can observe and interact with the game to find bugs and verify behavior.
- **Approach**: Playwright test (`tests/ai-play.ts`) with `AIGameController` class that provides high-level commands and observation tools.
- **Capabilities**:
  - `observe(label)`: Take timestamped screenshot + log observation
  - `getGameState()`: Extract phase, HP, ammo, bloom, score from DOM
  - `reportState()`: Console log current game state
  - `clickStandardMode()`: Start Standard/Best-of mode
  - `enterHolsterZone()`: Move mouse into holster to begin countdown
  - `focusTaps(count)`: Press Space N times to shrink bloom
  - `waitForDraw()`: Wait for DRAW phase (~3.5s)
  - `aimAt(target)`: Aim at 'head' | 'body' | 'miss-left' | 'miss-right'
  - `fire(pos)`: Click to fire at position
  - `waitForRoundEnd()`: Wait for round resolution
  - `diagnose()`: Check which DOM elements exist (holster, canvas, HUD, crosshair, cylinder, pads, buttons)
  - `checkForErrors()`: Listen for console errors and page errors
  - `printSummary()`: Print all observations taken during session
- **Outputs**:
  - Screenshots: `test-results/ai-play/step-NNN-label.png` (sequential, zero-padded)
  - Video: `test-results/ai-play-videos/*.webm` (full session recording)
  - Console: Real-time state reports + error detection
- **Run**: `npm run ai:play` (new script in `package.json`)
- **Script**: `scripts/ai-play.sh` (creates output dirs, runs via `npx tsx`)
- **Features**:
  - Headed browser via WSLg (visible on Windows desktop from WSL)
  - slowMo 400ms (visible automation, easy to follow)
  - Two-round test: first round headshot, second round bodyshot
  - Error tracking (console + pageerror events)
  - 30s inspection window after test completes
  - Automatic diagnostics if elements missing
- **Use case**: AI can now "play" the game, capture what it sees, and report broken behavior — useful for regression testing, QA automation, and debugging issues that are hard to reproduce manually.

## 7. Smooth aim chase (2026-09-28, `src/ui/home.ts` only)

- Complaint: at DRAW the crosshair snapped holster→dirt-open, and every mouse move teleported it (only the arm was smoothed, not the aim).
- Fix: split aim into instant `aimTarget` (all pointer/touch input writes here via `aimFromClient`) + rendered `aimWorld` which `lerp`s toward it at ~20/s, delta-time safe. At DRAW entry the aim is seeded from the live pointer (`aimFromClient(pointerPx)` + `aimWorld.copy(aimTarget)`, still low/off-enemy since the pointer is in the holster zone), so the crosshair continues exactly where Focus left it — zero jump — then glides wherever the pointer goes.
- Hit registration uses the click point itself, so the chase is pure visual and cannot shift a shot. No phase/input/economy/spec changes.
- Verified: frame-sampled a scripted glide — monotonic steps, max 43px/50ms, no teleports; DRAW screenshot shows crosshair continuous at the holster; `typecheck` + `build:basic` + `size:basic` PASS, `ai:play` + `ai:play:mobile` zero errors.
