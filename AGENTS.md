# AGENTS.md — gamey

- Motive: ship one web game to `crazygames.com` and `poki.com` and pass both developer QA checks.
- One build with the CrazyGames SDK (user 2026-10-06; replaces the old no-sdk/with-sdk dual build): CrazyGames Basic Launch allows the SDK (ads are disabled there, requests fail with `adsDisabledBasicLaunch`). The SDK v3 loads at runtime from its CDN inside `CrazyGamesAdapter` (not bundled); ads stay OFF via `ADS_ENABLED=false` in `src/portal/config.ts` until CrazyGames promotes the game to Full, then flip it and re-upload. Game code never touches an SDK: everything goes through `PortalAdapter`, and "watch ad" buttons render only when `adapter.adsEnabled` (no dead rewarded buttons). If the SDK can't load (adblock, offline, other sites, `?nosdk=1`) the adapter falls back to `NoopAdapter` and the game plays. A future Poki build gets its own adapter.
- Source of truth for portal rules: `specs/crazygames/` (sizes, gameplay, ads, accounts, multiplayer, covers, checklist). Check it before adding external requests, logins, promos, fullscreen buttons, or ad logic — all are QA fail risks.
- Memory: read `context/` before coding — dated files (newest wins, e.g. `context/2026-10-04.md`; earlier ones still hold locked design not repeated later) hold locked game design (modes, duel rules, adapter, engine). `specs/` holds portal rules; `context/` holds our decisions. Check both. If context is written multiple times in one day, append to `context/YYYY-MM-DD.md` (same-day file, never overwrite with a fresh file, never start a second file for the same date).
- Stack: TS + Vite + raw Three.js + `cannon-es` (ragdoll only, wired Phase 2). Singleplayer now, multiplayer-client seam later (lowest priority).
- Commands: `npm install`, `npm run dev` (port 5174; `basic.html?nosdk=1` skips the SDK), `npm run typecheck`, `npm run build` → `dist/` (CrazyGames entry `basic.html`), `npm run size` (fail if dist >20MB, the mobile-homepage budget), `npm test` (= typecheck + build + size + test:physics), `npm run test:physics` (pure-Node refresh-rate check, `tests/physics-refresh.test.ts`, via the `tsx` devDependency), `npm run build:models` (regenerates `public/models/cowboy_{hero,outlaw}.glb` headless from `blender/cowboys.blend` via `scripts/blender/build_glbs.py`; needs `blender` on PATH), `npm run build:street` (regenerates `public/models/street.glb` from code alone via `scripts/blender/build_street.py`, `--factory-startup`, no .blend; deterministic). AI self-play: `npm run ai:play` (desktop 1920x1080) / `npm run ai:play:mobile` (800x450) / `npm run ai:play:all` (both); overrides `VIEWPORT=WxH HEADLESS=1 INSPECT_SECS=n`. No linter yet.
- Entrypoint: `basic.html` -> `src/main.ts`: `createCrazyGamesAdapter()`, `await adapter.init()` (never rejects), then `boot(root, adapter)` in `src/ui/home.ts` (there is no `src/boot.ts`). `vite.config.ts`: one input, `dist/`, manualChunks three/cannon, `assetsInlineLimit:0`, no sourcemaps, `base:"./"` relative paths. Saves: SDK Data module (key `gamey.v1`; a pre-SDK localStorage save is copied in once), SafeStore in no-SDK mode.
- Workflow: single branch. Commit and push directly to `main` (`origin` = `git@github.com:AnantGaur10/gamey.git`). No feature branches, no PRs, no merges: `main` is the single source of truth.
- Physics clock (spec `specs/crazygames/gameplay.md:12`, must hold at 60/144/165Hz): ALL physics (DuelMachine, bullets, ragdoll) advances only inside `createFixedStepper().advance(dt, fixedFn)` from `src/game/fixedStep.ts` (fixed `STEP` = 1/60s, dt clamped to `MAX_FRAME_DT`). Rendering never steps physics; it interpolates the last two physics states by the returned `alpha` (`ragdoll.sync(alpha)`, `renderBullets(alpha)`). Never advance anything by frame count. `npm run test:physics` guards this.
