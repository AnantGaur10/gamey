# AGENTS.md — gamey

- Motive: ship one web game to `crazygames.com` and `poki.com` and pass both developer QA checks.
- Dual-build strategy (required): maintain TWO builds from one codebase — `no-sdk` (no ads SDK, for CrazyGames Basic Launch) and `with-sdk` (CrazyGames Full + Poki SDK integration). Never fork game logic; gate all SDK/ads calls behind an adapter + build flag so `no-sdk` runs clean with ads disabled (no freezes, no dead rewarded buttons).
- Source of truth for portal rules: `specs/crazygames/` (sizes, gameplay, ads, accounts, multiplayer, covers, checklist). Check it before adding external requests, logins, promos, fullscreen buttons, or ad logic — all are QA fail risks.
- Memory: read `context/` before coding — dated files (newest wins, e.g. `context/2026-10-04.md`; earlier ones still hold locked design not repeated later) hold locked game design (modes, duel rules, adapter, engine). `specs/` holds portal rules; `context/` holds our decisions. Check both. If context is written multiple times in one day, append to `context/YYYY-MM-DD.md` (same-day file, never overwrite with a fresh file, never start a second file for the same date).
- Stack: TS + Vite + raw Three.js + `cannon-es` (ragdoll only, wired Phase 2). Singleplayer now, multiplayer-client seam later (lowest priority).
- Commands: `npm install`, `npm run dev` (basic), `npm run dev:full`, `npm run typecheck`, `npm run build:basic` → `dist-basic/` (CrazyGames entry `basic.html`), `npm run build:full` → `dist-full/` (entry `full.html`), `npm run size:basic` (fail if dist-basic >20MB), `npm test` (= typecheck + build:basic + size:basic + test:physics), `npm run test:physics` (pure-Node refresh-rate check, `tests/physics-refresh.test.ts`, via the `tsx` devDependency), `npm run build:models` (regenerates `public/models/*.glb` headless from `blender/cowboys.blend` via `scripts/blender/build_glbs.py`; needs `blender` on PATH). AI self-play: `npm run ai:play` (desktop 1920x1080) / `npm run ai:play:mobile` (800x450) / `npm run ai:play:all` (both); overrides `VIEWPORT=WxH HEADLESS=1 INSPECT_SECS=n`. No linter yet.
- Entrypoints: `src/main-basic.ts` + `createNoopAdapter` (zero SDK bytes, verified by grep) vs `src/main-full.ts` + `createCrazyGamesAdapter` stub; both call shared `boot(root, adapter)` in `src/ui/home.ts` (there is no `src/boot.ts`). Switch by `GAMEY_BUILD=basic|full` in `vite.config.ts` (`__GAMEY_BUILD__` define — currently unused in `src/`, build selection is by entry file — separate html inputs, manualChunks three/cannon, `assetsInlineLimit:0`, no sourcemaps, `base:"./"` relative paths).
- Workflow: single branch. Commit and push directly to `main` (`origin` = `git@github.com:AnantGaur10/gamey.git`). No feature branches, no PRs, no merges: `main` is the single source of truth.
- Physics clock (spec `specs/crazygames/gameplay.md:12`, must hold at 60/144/165Hz): ALL physics (DuelMachine, bullets, ragdoll) advances only inside `createFixedStepper().advance(dt, fixedFn)` from `src/game/fixedStep.ts` (fixed `STEP` = 1/60s, dt clamped to `MAX_FRAME_DT`). Rendering never steps physics; it interpolates the last two physics states by the returned `alpha` (`ragdoll.sync(alpha)`, `renderBullets(alpha)`). Never advance anything by frame count. `npm run test:physics` guards this.
- When a stack lands: update this file with exact build/test/lint commands, entrypoints, and how each build (`no-sdk` vs `with-sdk`) is produced.
